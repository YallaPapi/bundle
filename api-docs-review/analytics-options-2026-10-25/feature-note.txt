Verified contract: x-api-key; GET /analytics/social-account and /raw each require one teamId and platformType, return socialAccount and items; no documented bulk profile endpoint or date filters/pagination on these endpoints. GET /analytics/post/bulk accepts postIds array 1-60 and platformType with page>=1 and limit1-20, returns results and pagination. Each item has createdAt/updatedAt. Paid plan required. Default collection 24 hours; analytics retention30 days. Instagram normalized profile views are profile visits in rolling30d, followers count is current; post views/video plays are lifetime snapshots. Raw profile payload documented as optional organization-enabled with totals30d daily breakdown. No force refresh or platform writes for this review.
Application proposal: one daily job fetches account snapshots, optionally bulk post snapshots, saves history and aggregates locally for a Sheets/chart or dashboard. Daily follower net growth from aligned daily snapshots; cumulative post-view differences only approximate interval gains and must preserve post IDs and coverage. Missing accounts or stale values must not be treated as zero. Sample live GETs below check actual data availability before recommending a daily-views implementation.

Live checks 2026-10-25: normalized account analytics returned six snapshots for landonandstuff (latest followers=0); raw account analytics returned items=[] so raw daily breakdown availability is unconfirmed and cannot be assumed. Bulk GET with two post IDs from different teams succeeded and returned historical lifetime-view snapshots with page/limit pagination. At least 24-hour snapshot view gains can be estimated from these histories; exact calendar-day Instagram view counts are not established by this test.
